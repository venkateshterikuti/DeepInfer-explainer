The journey of one request

Follow a single question through the machine

Every chapter is a stop on this route. Links go to the chapter that explains each step.

1 · Arrive

JSON becomes token IDs

A Chat Completions call arrives. Recipe converts it to a conversation, renders the V4.1 prompt and encodes it, with control tokens placed by position so user text can't forge them.

12 The front door →

2 · Images

Pictures become tokens

Each image placeholder expands into rows of 42-pixel tokens. In production a separate vision-encoder GPU turns pixels into embeddings for the prefill tier.

12 The front door →

3 · Reuse

Skip what's already computed

The prompt's prefix is looked up in the KV store. Block KV says how much hit; the saved sliding-window state decides whether the last 128 tokens must be recomputed, and bounded replay keeps that recompute short.

07 The cluster → 08 Bounded replay →

4 · Prefill

Read the rest of the prompt

A prefill engine at EP2–8 pushes the uncached tokens through the first 20 layers in chunks (a token cap in the release, a time budget in production), replays only the last 140 tokens through the 20 layers that take their KV from earlier ones, and writes KV pages and a window-state slot as it goes.

05 Scheduling → 02 The model → 03 The engine →

5 · Hand-off

Move to a wide decode tier

The request's KV moves to a decode instance spread over 64–128 GPUs, where attention runs data-parallel and experts are spread out and rebalanced as traffic shifts.

06 Parallelism → 04 KV memory →

6 · Decode

Step after step

Each step a drafter proposes 5 tokens, the scheduler decides which are worth checking, FP8/FP4 kernels run the model, and the sampler accepts, resamples or masks by grammar, while the CPU is already preparing the next step.

7 · Return

Tokens become events

Token IDs stream back; Recipe buffers split characters, switches between reasoning, text and tool calls on special IDs, and streams tool arguments as JSON. Benchmarks and exact baselines keep all of it honest.
