Numbers and kernels

Below the scheduler, everything is bytes and tiles. V4.1 keeps weights and KV in 8 and 4 bits with shared scales, and DeepInfer runs on DeepSeek's own kernel libraries, on two kinds of hardware.

Number formats

Fewer bits, shared scales

Decode reads bytes. Halving the bytes nearly halves the time, as long as the numbers stay accurate enough.

Bytes are time

Each halving pays twice

A memory-bound step costs bytes read ÷ bandwidth. Going from 16-bit to 8-bit weights halves the bytes; 4-bit halves them again. Smaller weights also leave more HBM for KV, which means bigger batches.

Block scaling

One scale per block of values

A low-bit number has a tiny range, so values are stored relative to a scale shared by a block. V4.1's FP8 weights use 32×32 blocks; their scales are ue8m0: an 8-bit exponent with no mantissa, so every scale is an exact power of two and rescaling is just exponent arithmetic.

Four bits

Eight magnitudes and a sign

FP4 (E2M1) can represent only 0, 0.5, 1, 1.5, 2, 3, 4 and 6, plus a sign. MXFP4 groups 32 such values under one power-of-two scale; V4.1 uses it for routed-expert weights and the indexer's keys. The main KV cache uses FP4 values with an FP8 (e4m3) scale per 16 values: finer, more accurate scales.

What it buys

Bytes per value, all in

Counting the scales, BF16 costs 16 bits per value, FP8 with 32×32 blocks about 8.01, MXFP4 4.25, and FP4 with an e4m3 scale per 16 values 4.5. Experts dominate weight bytes, KV dominates per-request bytes; both go to about 4 bits.

Kernels

A shelf of DeepSeek libraries

The libraries

Each one owns a hot loop

FlashMLA runs the attention, including the sparse and compressed paths. DeepGEMM runs the FP8/FP4 matrix multiplies, from dense projections to grouped expert GEMMs. DeepEP moves tokens to experts and back, and fetches Engram rows held by other ranks. DeepSelect does top-k for the indexer and the sampler. TileKernels (a pip package) supplies fused SwiGLU-plus-quantize (and MoE gating on Ascend), and the repo adds about 30 TileLang ops of its own.

Mega MoE

One kernel for the whole MoE layer

An unfused MoE layer runs dispatch, two expert GEMMs, the activation and combine as separate steps after the gate, with intermediates going through memory in between. When the whole expert-parallel group sits inside one NVLink domain, DeepInfer runs the gate (itself a fused DeepGEMM call on GPUs) and then a single DeepGEMM mega MoE kernel for everything else: tokens move through symmetric memory, the shared expert can be folded in, and expert loads are counted for EPLB on the way. DeepSeek reports it is significantly faster than unfused MoE at every EP size and batch size in that setting.

TileLang

One op, two backends

Engine-specific kernels (sampling, KV stores, state-cache copies, window indexing, the zero-overhead-scheduling gathers, draft scheduling, grammar masks) are written in TileLang. There are about 29 per backend; most exist in both cuda/ and asc/, a few in only one. ops.py imports whichever backend the platform names and raises a clear error if a kernel is missing there; the top-level file holds the wrapper and, for nearly every op, its reference tests.

Two platforms

SM100 and Ascend 950

The same engine builds for NVIDIA SM100 (CUDA 13) or Huawei Ascend 950 (CANN 9.2), chosen by DEEPINFER_ACCELERATOR. FlashMLA and DeepSelect compile for either target; DeepEP and DeepGEMM have Ascend ports. deep_cluster looks up the NUMA node of each process's accelerator (or InfiniBand card) and binds both its CPU threads and its memory there.

Scales as raw exponents

models/v4_modules/engram.pysource
"""Pack the ue8m0 scales represented in fp32 into
int32 (CUDA) / int16 (ASC), 4/2 per group."""
assert x.dtype == torch.float32 and x.size(-1) % 4 == 0
x_int32 = x.view(torch.int32)
# a power of two has an all-zero mantissa
assert (x_int32 >= 0).all() and (x_int32 & 0x7FFFFF == 0).all()
# keep only the 8 exponent bits
return torch.floor_divide(x_int32, 1 << 23).to(torch.uint8).view(PLATFORM.fp8_sf_type)

A ue8m0 scale is literally the exponent byte of a float32 whose mantissa is zero. The code checks the mantissa bits are clear, shifts the exponent down 23 bits and packs four of them per 32-bit word on CUDA, or two per 16-bit word on Ascend.

The model loader insists on this layout: the config must say FP8 with 32×32 weight blocks, FP4 experts, dynamic activation scaling and ue8m0 scales, or it refuses to load.

DeepSeek notes that its internal FlashMLA has one extra hand-tuned SASS optimization, making the decode kernel 5–10% faster; end to end the public and internal stacks are within 5%.
