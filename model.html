The model sets the rules

DeepSeek V4.1 Flash is a 40-layer mixture of experts with two kinds of attention cache, layers that borrow each other's keys, and a lookup table of n-grams. Each choice becomes engine code.

Inside one layer

Five parts, one token's trip

Follow a single token through one layer. Each part answers a different cost problem from chapter 01.

Residual streams · mHC

Several lanes instead of one

A classic transformer carries one residual vector from layer to layer. V4.1 carries several parallel streams. Before each sub-layer, learned weights mix them into one input; afterwards, the result is written back into every stream with its own weight. The code calls these hyper-connections (hc.py).

Attention · near

Exact attention over the last 128 tokens

Every layer attends precisely to a sliding window of the most recent 128 tokens. That window's keys and values are small and bounded: the cache never grows past 128 entries per layer, no matter how long the conversation.

Attention · far

Compressed, then selected

Everything older is reached through a compressed cache: a gated low-rank compressor folds every r tokens into one entry, stored in 4-bit floating point. A small indexer scores entries with relu(q·k)·w and the layer attends only to the top-k. Long context gets cheap without a dense scan.

Feed-forward · MoE

Six experts out of 384

A router scores 384 experts and sends the token to six of them, plus one shared expert that sees every token. Most of the model's parameters live here, and each token touches only a sliver of them.

Engram · layers 1 and 14

A lookup, not a computation

Two layers add an Engram: the last few tokens are hashed as 2-, 3- and 4-grams into huge embedding tables, the rows are fetched, projected and gated into the hidden state. Memorized phrases come from a table lookup instead of from matrix multiplies.

Across layers

Layers that reuse each other's work

The biggest savings in V4.1 come from layers not doing their own copy of a job.

Shared KV

Four layers write, the rest read

Only layers 2, 8, 14 and 20 produce long-range KV. Every other layer reads the KV of the nearest source layer below it. The indexer modules are shared on a similar schedule (sources 2, 8, 14, 20, 24, 28, 32, 36). DeepInfer derives this map once in SharedLayerTopology.

YOCO split

The upper half doesn't read the prompt itself

The later layers are "consumer" layers: their long-range KV is projected from the hidden state of the last early layer, as in Microsoft's You Only Cache Once. They still keep their own sliding window. Chapter 08 shows how this lets prefill skip most of their work.

Draft layers

Three extra layers propose the future

On top sit three DFlash draft layers with smaller MoEs (128 experts, top-3). They read hidden states from target layers 37, 38 and 39 and propose a block of next tokens for speculative decoding (chapter 09).

Consequence

Every feature becomes engine code

Two caches with different lifetimes, cross-layer metadata, a replay path, an indexer cache, hashed tables sharded across GPUs, and a drafter with its own CUDA graphs. The rest of this site is how DeepInfer handles each one.

384 + 1 experts, top-6

Tokens scatter across experts, so the experts are spread over many GPUs and tokens travel to them.

Huge embedding tables addressed by hashing n-grams of a compressed vocabulary.

How much memory does one token cost?

KV bytes per token decide how many requests fit on a GPU and whether a cache can live on disk. Compare attention designs, then turn the knobs that V4.1 turns.

Reference designs use published shapes: GPT-3 175B (96 layers × 96 heads × 128), Llama-3-70B GQA (80 layers × 8 KV heads × 128), DeepSeek-V3 MLA (61 layers × 576 latent), all at 16 bits. The knob row starts at an estimate for V4.1 from its config: 4 KV source layers, 512-value entries in FP4 with a scale per 16, r = 2, plus a 128-dim FP4 index key.
